# Fractal-patterned-mass topology

Computation and plotting for the **Cantor chain / Sierpiński carpet / Menger sponge**
fractal-patterned-mass results of Chapter 7.

This project studies what happens to the topology of Wilson–Dirac (Qi–Wu–Zhang-type)
models in 1D, 2D, and 3D when the on-site mass is given a **fractal spatial pattern**
instead of being uniform. Three diagnostics are used, one per dimension:

| Fractal | Dim | Diagnostic (observable) | What it measures |
|---|---|---|---|
| Cantor chain | 1D | **polarization** (real-space Zak phase) | bulk topological invariant `P ∈ [0, ½]` |
| Sierpiński carpet | 2D | **Bott index** | integer Chern-like invariant |
| Menger sponge | 3D | **Witten effect** `δQ(R)` and **near-zero LDOS** | monopole-induced charge / mid-gap states |

The code is deliberately split into a small, reusable **library** (`project_tools/`)
and two **orchestration scripts** you actually run (`compute_data.py`, `plot_data.py`).

```
FractalsProject/
  compute_data.py      ← run this: all data computation (NO plotting)
  plot_data.py         ← run this: all plotting / figure assembly
  README.md            ← this file
  data/                ← saved results (nested .npz tree; see “How results are stored”)
  project_tools/       ← the computation library, imported by the two scripts
    lattice.py           fractal geometry (pure NumPy, no physics)
    model.py             the single Wilson–Dirac model builder
    observables.py       polarization, bott_index, near_zero_ldos
    witten.py            monopole charge response + δQ(R) integrator
    io.py                canonical naming + nested .npz save/load

```

**Rule of thumb:** compute lives in `compute_data.py`, plotting lives in `plot_data.py`.
Both are thin drivers that import building blocks from `project_tools`. You can also
import any library function directly in a notebook or a scratch script.

The project targets **Python 3.13** and depends on:

- `numpy`, `scipy` — arrays and dense/sparse eigensolvers
- `matplotlib` — plotting
- `joblib`, `tqdm`, `tqdm_joblib` — parallel phase-diagram sweeps with progress bars
- `hypercubic` — the tight-binding engine (bundled here as a sibling package)

```bash
pip install numpy scipy matplotlib joblib tqdm tqdm-joblib
```

`hypercubic` is a general-purpose library used across several projects; it is not
specific to this one. You only need to know its entry point, `hypercubic_grid_model(...)`,

Run the scripts from the project root so that `project_tools` and `hypercubic` are importable
and `io.DATA_ROOT` (which is `<repo>/data`) resolves correctly.

## Core concepts

Every calculation is defined by a handful of orthogonal choices.

### 1. Fractal (sets the dimension)

`"cantor"` (1D), `"carpet"` (2D), `"sponge"` (3D). Each is generated by a substitution
system from a seed pattern (`lattice._seed`):

- **Cantor:** `[1, 0, 1]` — keep the outer thirds, drop the middle.
- **Carpet:** 3×3 with the center removed.
- **Sponge:** 3×3×3 with all cells satisfying "≥2 coordinates == 1" removed.

The seed's value `1` marks a **frame** ("kept") site; `0` marks a **complement**
("hole") site.

### 2. Hole treatment (how complement sites are handled)

Passed as `hole_treatment=` to `model.build_model` (and as `method=` in the Witten/LDOS APIs).
Valid values (`model.HOLE_TREATMENTS`):

| Value | Meaning |
|---|---|
| `substituted` | **Main case.** Complement sites are kept but given a *different* mass `M_alt`. |
| `site_elim` | Complement sites are deleted (vacancies). |
| `renorm` | Complement sites are Schur-eliminated at `E=0` (downfolded effective Hamiltonian). |
| `cube` | The lattice is filled solid (all sites become frame) — a no-fractal reference. |

Only `substituted` uses two independent masses. `site_elim`, `renorm`, and `cube`
use a **single mass `M`** (see [gotchas](#conventions--gotchas)).

### 3. The two masses

The on-site mass profile (`model.sector_mass`) is:

```
frame site (sector 1) → M
complement (sector 0)  → M_alt      # substituted only; otherwise M_alt is pinned to M
```

The Wilson–Dirac model is (for `t = B = 1`) topological for `0 < M < 4` in the uniform
case. The phase diagrams sweep `(M, M_alt)`.

### 4. Size knobs — generation `n` vs linear size `L`

Two **independent** notions of "size":

- **`n` (generation):** how many substitution iterations → how much fractal *detail*.
- **`L` (linear size):** number of sites along one axis.

`L` is produced from three build knobs (all pure `np.repeat`/`np.tile`, see `lattice.py`):

```
L = block_scale * 3**max(n, upscale_to_n)      (× 2 per axis if pasted)
```

- **`block_scale`:** replace every site with a `block_scale`-sided solid block (grid refine).
- **`upscale_to_n`:** cell-replicate the order-`n` fractal up to a higher generation's
  footprint *before* block expansion (coarser fractal at a finer-generation size).
- **`pasted`:** tile the whole pattern `2×…×2` (used for the sponge Witten construction —
  "tiled" in the chapter). This is `np.tile`, geometrically distinct from `np.repeat`.

Use `lattice.system_length(n, upscale_to_n=..., block_scale=..., pasted=...)` to compute `L`.

> **Why both `upscale_to_n` and `block_scale`?** They are conveniences for sweeping
> sizes without hand-computing `L`. Because both are `np.repeat`, `(n, L)` alone
> uniquely determines the lattice, so **stored runs are identified by `n` and `L` only**.

### 5. Observable

`polarization` (1D), `bott_index` (2D), `near_zero_ldos` (any D), and the Witten
`δQ(R)` response (3D). These are orthogonal to *how* the model was built — they take
an already-built model plus a `params` dict.

### 6. The `params` dict

Physics parameters passed at solve time (not build time):

```python
params = dict(M=2.0, M_alt=-0.10, t=1.0, B=1.0,
              disorder_strength=0.0, disorder_seed=0)
# 3D / Witten runs also use:  M_prime=0.01, gauge="N", g=0.0
```

- `disorder_strength` — box disorder (variance 1/12); phase-diagram sweeps use a tiny
  `1e-5` to lift degeneracies. `disorder_seed < 0` means a random seed.
- `M_prime` — the pseudo-scalar (Γ₅) mass term, required for the 3D Witten construction.
- `gauge` — Dirac-string gauge, `"N"` (north) or `"S"` (south).
- `g` — monopole charge: `0` = background, `1` = monopole present.

## The library (`project_tools`)

### `lattice.py` — geometry (pure NumPy)

```python
build_lattice(name, n, *, upscale_to_n=None, block_scale=2, pasted=False) -> ndarray[int]
system_length(n, *, upscale_to_n=None, block_scale=2, pasted=False)       -> int
fractal_lattice(name, n, *, upscale_to_n=None)   # fractal pattern only
block_upscale(lat, block_scale)                  # the L knob
substitution_system(seed, n)                     # generic substitution
```

Produces the 0/1 sector array. No physics, no `hypercubic` dependency.

### `model.py` — the Wilson–Dirac builder

```python
build_model(fractal, n, *, hole_treatment="substituted", pbc=False,
            upscale_to_n=None, block_scale=2, pasted=False,
            pseudo_scalar=None) -> hypercubic.Model
```

Everything that knows about the d-vector, the pseudo-scalar term, the monopole Peierls
phase, and the sector mass lives here. `pseudo_scalar` defaults to `True` in 3D.
`hole_treatment` is validated against `HOLE_TREATMENTS`.

### `observables.py` — diagnostics

```python
polarization(model, params) -> float            # 1D real-space Zak phase, returns |P| ∈ [0, ½]
bott_index(model, params)   -> int              # 2D Bott index
near_zero_ldos(model, params, k_center, *, method="substituted",
               solver="ed", k_solve=None) -> dict(ldos=..., energies=...)
```

`near_zero_ldos` details:
- `k_center` — number of central near-zero modes to keep (**forced even**).
- `method` — `substituted`/`site_elim`/`cube` solve the built Hamiltonian; `renorm`
  solves the Schur-complement (dense) effective Hamiltonian.
- `solver` — `"ed"` (dense full spectrum) or `"sparse"` (shift-invert `k_solve` states
  near `E=0`, keep the central `k_center`). `k_solve` is forced even and must be
  `≥ k_center + 2`. **`renorm` requires `solver="ed"`** (its effective Hamiltonian is
  dense) and raises otherwise.

### `witten.py` — monopole charge response

```python
witten_run(fractal="sponge", *, n, M, M_alt=None, method="substituted",
           block_scale=2, pasted=True, M_prime=0.01, gauge="N",
           upscale_to_n=None, t=1.0, B=1.0, pbc=False) -> dict
dQ_of_R(dQ_field, resolution=300) -> (R_vals, dQ)
```

`witten_run` builds the model once, solves at `g=0` (background) and `g=1` (monopole),
and returns the induced-charge field plus spectra. `dQ_of_R` integrates the induced
density into cumulative charge `δQ(R)` using an exact sphere-on-cubic-grid overlap (so
the curve is smooth, not a staircase). For a monopole in a topological insulator the
half-filling response approaches `δQ → -½`.

### `io.py` — naming and persistence

```python
case_tag(**params) -> str                        # canonical filename stem
result_path(kind, meta, *, root=None) -> Path    # nested path from metadata
save_result(kind, meta, *, root=None, **arrays) -> Path
load_result(path) -> (arrays, meta)
```

`kind ∈ ("phase_diagram", "witten", "ldos")`. Each `.npz` embeds its full parameter
set as JSON under `__meta__`, so **every file is self-describing** — there is no
external index to keep in sync.

## How results are stored

Results live under `data/`, one subtree per observable family, nested by the parameters
you most often browse, with a self-describing `.npz` per run:

```
data/
  phase_diagram/<fractal>/L<L>/<tag>.npz
      # arrays: grid, M_vals, M_alt_vals
  witten/<geometry>/<method>/L<L>/<tag>.npz
      # arrays: R, dQ, charge_bg, charge_mono, dQ_field, eigenvalues_bg, eigenvalues_mono
  ldos/<geometry>/<method>/L<L>/<tag>.npz
      # arrays: ldos, energies
```

- `<fractal>` is `cantor` / `carpet` (phase diagrams).
- `<geometry>` folds fractal + tiling: `tiled_sponge` / `untiled_sponge` / `cube`.
- The `<method>` directory level is omitted when it would merely repeat the fractal name
  (so the solid cube reference lands in `cube/L12/`, not `cube/cube/L12/`).
- `<tag>` is `io.case_tag(...)`, e.g. `cantor_n3_L81_substituted` or
  `sponge_n1_L24_M+2.00_Malt-0.10_Mp+0.01_t1_B1_gN_substituted_pasted`.

`save_result` creates any missing subdirectories automatically. Runs are identified by
`n` and `L` (not `block_scale`/`upscale_to_n`); `M_alt` is part of the identity only for
`substituted`; `pasted` appears only for the sponge.

**Loading anything back:**

```python
from project_tools import io
arrays, meta = io.load_result(io.result_path("phase_diagram",
    dict(fractal="cantor", method="substituted", n=3, L=81)))
grid = arrays["grid"]           # (M_alt_res, M_res)
```

## Computing data (`compute_data.py`)

Open the file, set the flags at the top of `main()`, adjust the parameter blocks, and run.
As shipped, `main()` recomputes the **phase diagrams**:

```python
RUN_CANTOR = True     # 1D polarization phase diagrams
RUN_CARPET = True     # 2D Bott-index phase diagrams
```

Both sections call a shared local helper:

```python
run_phase_diagrams(fractal, cases, *, M_res, M_alt_res, M_range, M_alt_range, n_jobs=25)
```

where `cases` is a list of `(n, upscale_to_n, block_scale)` tuples. Each case runs a
parallel `(M, M_alt)` sweep (`compute_data.phase_diagram`) and saves one
`phase_diagram` result. The cases are grouped by `L` so all generations at a given size
finish before moving to the next (larger) size.

Cantor uses `M, M_alt ∈ [-1, 5]` at 121×121; carpet uses `[-1, 9]` at 101×101 —
ranges and resolutions are passed explicitly at each call site (no hidden defaults).

The **grid convention** is `grid[i, j] ↔ M = M_vals[j], M_alt = M_alt_vals[i]`, i.e.
shape `(M_alt_res, M_res)`. Failed points use a sentinel: `NaN` (cantor) or `100` (carpet).

> **Witten and LDOS** are not wired into `main()` (they were one-off runs). Compute them
> via the library functions — see the [worked examples](#worked-examples) below — and
> save with `io.save_result`.

## Plotting data (`plot_data.py`)

Open the file, set the flags at the top of `main()`, and run:

```python
PLOT_PHASE_DIAGRAMS = False
PLOT_WITTEN         = True
PLOT_LDOS           = False
```

The reusable plot functions (importable directly):

| Function | Purpose |
|---|---|
| `plot_phase_diagrams(fractal, pairs=None)` | Grid of all phase diagrams for a fractal: **columns = n, rows = L**; missing `(n, L)` cells left blank. `pairs=[(n, L), …]` restricts the set. |
| `plot_dQ_vs_R(result, ax=None, normalize_L=True, label=None)` | Witten `δQ` vs `R/L` (or `R`); pass a shared `ax` to overlay several sizes. |
| `plot_ldos(result, cmap="viridis")` | Near-zero LDOS: 1D line, 2D image, or 3D grid of z-slices. |
| `plot_spectrum(result)` | Side-by-side scatter of background (g=0) and monopole (g=1) spectra. |
| `plot_result(path)` | Dispatch to the right plot based on the file's top-level `data/<kind>/` folder. |

The per-result functions accept **either** a path to a saved `.npz` **or** an
`(arrays, meta)` pair. `plot_phase_diagrams` instead takes a fractal name and assembles
the grid from every saved result for that fractal.

## Worked examples

### A. Cantor / carpet phase diagram (compute)

Recompute one cantor case directly (bypassing `main()`):

```python
from project_tools import io, lattice
from compute_data import phase_diagram

grid, M_vals, M_alt_vals = phase_diagram(
    "cantor", n=3, M_range=(-1.0, 5.0), M_alt_range=(-1.0, 5.0),
    M_res=121, M_alt_res=121, upscale_to_n=4, block_scale=1, n_jobs=-1,
)
meta = dict(fractal="cantor", method="substituted", n=3,
            L=lattice.system_length(3, upscale_to_n=4, block_scale=1))  # L = 81
io.save_result("phase_diagram", meta, grid=grid, M_vals=M_vals, M_alt_vals=M_alt_vals)
```

### B. Phase diagram (plot)

```python
import matplotlib.pyplot as plt
from plot_data import plot_phase_diagrams

plot_phase_diagrams("cantor")                             # full n×L grid
plot_phase_diagrams("carpet", pairs=[(2, 27), (3, 27)])   # just two panels
plt.show()
```

### C. Sponge Witten effect (compute)

```python
from project_tools import witten, io, lattice

res = witten.witten_run(
    "sponge", n=1, M=2.0, M_alt=-0.10, method="substituted",
    block_scale=2, pasted=True, M_prime=0.01, gauge="N",
)
R, dQ = witten.dQ_of_R(res["dQ_field"], resolution=300)

L = lattice.system_length(1, block_scale=2, pasted=True)   # L = 12
meta = dict(fractal="sponge", method="substituted", n=1, L=L, pasted=True,
            M=2.0, M_prime=0.01, gauge="N", t=1.0, B=1.0,
            M_alt=-0.10)   # include M_alt ONLY for substituted
io.save_result("witten", meta, R=R, dQ=dQ,
               charge_bg=res["charge_bg"], charge_mono=res["charge_mono"],
               dQ_field=res["dQ_field"],
               eigenvalues_bg=res["eigenvalues_bg"],
               eigenvalues_mono=res["eigenvalues_mono"])
```

For a single-mass method (`site_elim` / `renorm` / `cube`), pass `method=...`, drop
`M_alt` from `meta`, and (for `cube`) omit `pasted` if you want it under `data/witten/cube/`.

### E. Near-zero LDOS (compute)

```python
from project_tools import model, observables, io, lattice

m = model.build_model("sponge", 1, hole_treatment="substituted",
                      pbc=False, block_scale=2, pasted=True, pseudo_scalar=True)
params = dict(M=2.0, M_alt=-0.10, t=1.0, B=1.0, disorder_strength=0, disorder_seed=0,
              M_prime=0.01, gauge="N", g=0.0)

out = observables.near_zero_ldos(m, params, k_center=4,
                                 method="substituted", solver="sparse", k_solve=12)

L = lattice.system_length(1, block_scale=2, pasted=True)   # L = 12
meta = dict(fractal="sponge", method="substituted", n=1, L=L,
            M=2.0, M_alt=-0.10, solver="sparse", pasted=True)
io.save_result("ldos", meta, ldos=out["ldos"], energies=out["energies"])
```

Use `solver="ed"` for full diagonalization (mandatory for `method="renorm"`); then
`k_solve` is ignored.

## Conventions & gotchas

- **Sectors:** lattice value `1` = frame → mass `M`; `0` = complement → mass `M_alt`
  (substituted) or removed / downfolded (site_elim / renorm) or filled solid (cube).
- **Single-mass methods:** `site_elim`, `renorm`, and `cube` use only `M`. `witten_run`
  pins `M_alt = M` for them, and `M_alt` is dropped from their filenames/identity. (For
  `renorm`, `M_alt` is pinned by convention — a uniform parent Hamiltonian is downfolded.)
- **`(n, L)` identifies a lattice.** Different `(upscale_to_n, block_scale)` combos that
  give the same `(n, L)` produce the identical lattice, so only `n` and `L` are stored.
- **`pasted` ≠ a repeat.** Tiling (`np.tile`) is geometrically different from block/upscale
  (`np.repeat`), so `pasted` is retained in the sponge's identity and directory (`tiled_`/`untiled_`).
- **Particle-hole symmetry** holds in all these models, so "central modes by index" ≡
  "smallest |E|". `near_zero_ldos` relies on this and guards that the kept band straddles `E=0`.
- **Polarization** returns `|P| ∈ [0, ½]` (`abs` collapses the ±½ branch-cut plateau of
  `np.angle`); topological ≈ `0.5`, trivial ≈ `0`.
- **Phase-diagram grid convention:** `grid[i, j] ↔ (M = M_vals[j], M_alt = M_alt_vals[i])`;
  sentinels `NaN` (cantor) / `100` (carpet) mark failed points.
- **Run from the repo root** so `io.DATA_ROOT = <repo>/data` resolves and imports work.

## Extending the project

- **A new fractal:** add its seed to `lattice._seed`; the substitution system, `system_length`,
  and the builder pick it up automatically (mind the dimension-dependent d-vector in `model.py`).
- **A new observable:** add a function `f(model, params)` to `observables.py`; it stays
  orthogonal to how the model was built. Wire it into `compute_data.py` and add a plotter
  to `plot_data.py`.
- **A new run to save:** build a `meta` dict with the identifying parameters and call
  `io.save_result(kind, meta, **arrays)`. Follow the identity rules above (only `n`/`L`
  for size; `M_alt` for substituted only; `pasted` for sponge only) so the file lands in
  the right place and is unambiguous.
- **Adding compute sections back to `main()`:** the Witten/LDOS blocks were removed for
  the current phase-diagram push; the worked examples above are drop-in templates if you
  want to re-add flag-gated sections.
